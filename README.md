# Push-рассылка

Отправляет push-уведомления по списку логинов из файла. База данных не нужна:
на вход только текст и файл с номерами.

## Запуск

```
run.bat
```

При первом запуске создаётся `venv`, ставятся зависимости и копируется `.env.example` в `.env`.
Откройте http://localhost:5001

Настройки лежат в `.env`: адрес push-сервиса, способ вызова, число потоков и таймаут.

## Какой формат файла выбрать

**Лучше Excel (.xlsx).** Кодировку там можно не учитывать: xlsx всегда хранит текст в Unicode.

| Формат | Что учесть |
|---|---|
| **.xlsx** ✅ | Колонку с номерами лучше сделать «Текстовой», иначе Excel может показать номер как `9,96555E+11`. Программа понимает и такой вариант. Можно несколько листов. |
| .csv | Сохранять как **«CSV UTF-8 (разделитель — запятая)»**. Обычный «CSV» в русской Windows сохраняется в cp1251, а там **нет букв ң ө ү**: они молча превратятся в `?`. Для номеров это не критично, программа читает и cp1251, но лучше использовать UTF-8. |
| .txt | Один номер на строку, UTF-8. |
| .xls | Не поддерживается: пересохраните как .xlsx. |

Логины ищутся в колонке с заголовком `login` / `логин` / `телефон` / `phone` / `номер`.
Если такой колонки нет, берётся первая. Из значения оставляются только цифры.
Пустые строки, строки неподходящей длины и дубли отбрасываются, перед запуском показывается сводка.

## Кириллица и кыргызские буквы

- Весь путь — UTF-8: страница, JSON-запросы, хранение, отправка. Для режима `path` текст
  кодируется в URL как UTF-8 (`ң` → `%D2%A3`).
- Над полем текста есть кнопки **ң ө ү Ң Ө Ү** на случай, если в раскладке нет этих букв.
- Текст проверяется на типичные ошибки, и их можно исправить одной кнопкой:
  - похожие буквы из других алфавитов: `ѳ` (фита), `θ`, `ҥ`, `ӊ`, `ұ` вместо `ө ң ү`;
  - латиница внутри русского или кыргызского слова: `Пoжалуйста` с латинской `o`, `ö ü ñ`;
  - признаки уже испорченного текста (`?` или `�` внутри слов).
- Отчёт `.csv` сохраняется в UTF-8 с BOM и с разделителем `;`, поэтому Excel открывает его без «кракозябр».

## Как устроена отправка

- Используется **один** способ вызова (`PUSH_MODE`), без перебора вариантов, чтобы не было дублей.
- Статусы:
  - `ok` — сервис ответил `{"message":"ok"}`;
  - `error` — сервис ответил ошибкой, можно безопасно повторить;
  - `unknown` — ответа нет (таймаут). Сообщение **могло дойти**, поэтому автоматически оно не повторяется.
- Повтор делается автоматически, только если не удалось соединиться: тогда запрос точно не ушёл.
- Каждый результат сразу пишется в `data/jobs/<id>/results.csv`. После паузы, сбоя или перезапуска
  рассылка продолжается с места остановки. Повторно может уйти не больше `PUSH_CONCURRENCY`
  сообщений, которые были в момент падения в полёте.
- Одновременно идёт только одна рассылка.
- Кнопки: пауза / продолжить / отменить / отчёт / «повторить ошибки» (создаёт новую рассылку только по `error`).

## Логи

Логи пишет loguru в UTF-8, поэтому кириллица в них отображается нормально.

| Куда | Что |
|---|---|
| консоль | всё от `LOG_LEVEL` |
| `data/logs/app_YYYY-MM-DD.log` | всё; новый файл каждый день, хранится `LOG_RETENTION_DAYS` дней |
| `data/logs/errors.log` | только предупреждения и ошибки (неуспешные отправки, падения); ротация по 10 МБ |

Во время рассылки раз в 30 секунд в лог пишется прогресс и скорость отправки.
Логи uvicorn и FastAPI тоже идут через loguru.

## Проверка без реальной отправки

```
venv\Scripts\python tools\mock_push_server.py
```
В `.env` укажите `PUSH_BASE_URL=http://127.0.0.1:7777`. Полученные сообщения пишутся в
`tools/mock_received.txt`: там можно проверить, что кыргызский текст дошёл без искажений.
